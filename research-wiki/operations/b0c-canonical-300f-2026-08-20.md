## 2. Schedule derivation (recorded before launch)

| quantity | value | derivation |
|---|---|---|
| camera-frame units | 5,700 | 19 × 300 |
| batch size | **2** | matches the 50-frame screening protocol's gradient-noise regime and STG's published N3V batch; avoids batch-dependent LR re-derivation. H100 memory is NOT the constraint (batch-2 full-raster peak ≈ 16 GB on V100) |
| iterations = optimizer updates | **36,000** | one optimizer step per iteration (batch = 2 renders accumulated per step) |
| total image presentations | 72,000 | 36,000 × 2 |
| presentations per unit | **12.63** | 72,000 / 5,700 — exactly the 50-frame screening exposure (12,000 / 950). The historical 300-frame 6k-iteration family gave only 2.1/unit |
| learning rates | position lr: exponential decay, `position_lr_max_steps: 36_000` (proportional horizon); all other lrs constant (family behavior) |
| densification | interval 100, from 500, **until 30,000** (~83%) — the ONE deviation from the 50f config's densify-to-end, following the 15k family's 80% precedent (`lora_route0_dynmask`: 12k/15k) to give a 6,000-iteration settling phase; chosen as the safer benchmark schedule, frozen here before any output |
| pruning / opacity reset | pruning inside the densification loop as in the family; `opacity_reset_interval: 40_000` — NEVER fires, preserving the family's never-reset semantics (the 50f config's 30,000 was also never-fires by construction) |
| primitive cap | 600,000 (ADAGS published budget). Expected to saturate early (the 50f run saturated by ~3.5k); the saturation iteration is a reported quantity |
| `route_logit_init` | **4.0 explicit** — the de-facto init of every historical run; post-repair YAML 0.0 would change the model family |
| projected runtime / memory | ~0.8 s/it on H100 → ≈ 8 h wall, ≈ 9 slot-h; ≈ 16 GB peak |
| iteration guard | `--max-train-iterations 36000` |

## 3. Frozen endpoint and reporting

* **Primary endpoint**: pooled PSNR over CLAMPED [0,1] renders across all
  300 held-out cam00 images, computed by the `--val` pass
  (`utils/mesh_utils.py`, batched `(1,3,H,W)` pooling per the 2026-08-20
  repair) on the **predeclared final checkpoint `chkpnt36000.pth`**.
* SSIM: `utils.loss_utils.ssim` (3DGS Gaussian-window). LPIPS:
  torchmetrics `LearnedPerceptualImagePatchSimilarity(net_type="alex",
  normalize=True)` — inputs in [0,1] mapped internally to [−1,1];
  DISCLOSED as differing from the STG/3DGS raw-[0,1] convention.
* Slice metrics (frames 0–49 / 50–99 / 100–149 / 150–199 / 200–249 /
  250–299), per-frame min, median, worst-decile mean: computed post hoc
  from the `--val` pass's saved renders/gt by a tracked script; 8-bit
  PNG basis disclosed.
* Also reported: realized primitive count + saturation iteration,
  wall time, peak memory, batch/iterations/presentations/per-unit
  exposure, training-loss convergence curve, late-sequence
  degradation (worst-decile membership by frame index).
* Checkpoints saved at 6k/12k/18k/24k/30k/36k. Intermediate cam00
  evaluations at those points are DESCRIPTIVE convergence data only.
  **cam00 selects nothing: not the schedule, not the stop, not the
  reported checkpoint.** No stop rule is declared; the run goes to
  36,000 unless a training-side failure (NaN loss, crash) ends it, in
  which case the run is reported as failed, not truncated-and-scored.

## 4. Comparison boundary (frozen wording)

B0-C is a SINGLE-SCENE, single-seed substrate benchmark. It must not be
compared to six-scene averages. Any reference to STG's published 33.52 dB
for this scene must disclose: (a) STG's published 300-frame result is six
independently trained 50-frame models in series, not one model; (b)
representation, initialization (per-frame triangulated clouds with a time
channel vs one frame-0 MVS cloud), and training schedule remain
unmatched; (c) the LPIPS convention differs as above. The 50-frame
screening parity result ([[stg-n3v-protocol-parity-2026-08-19]] Appendix
C) does not transfer to 300 frames and is not to be cited as if it did.
